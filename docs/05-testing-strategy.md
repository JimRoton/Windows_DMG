# Testing Strategy

The awkward fact: this is a Windows tool being developed on a Mac. The strategy
exists to make that a non-problem rather than a constant tax.

---

## 1. The core idea

**`Dmg.Core` has no Windows dependency.** Roughly 80% of the code and 90% of the
difficulty — container parsing, decryption, decompression, the extent index, the
cache, partition tables, filesystem probing, the VHD footer — is portable and runs
natively on macOS.

That means the hard half is developed and tested at full speed on the Mac, against
fixtures generated *by the Mac itself* with `hdiutil`. Only the attach/detach path
genuinely needs Windows.

| Suite | Runs on | Needs elevation | What it covers |
| --- | --- | --- | --- |
| `Dmg.Core.Tests` | macOS **and** Windows | no | Everything below the seam. The bulk of the suite. |
| `Dmg.Windows.Tests` | Windows | no | Mount logic against `FakeVirtualDiskService`; registry; letter resolution with injected data. |
| `Dmg.E2E.Tests` | Windows CI, and a local VM | **yes** | Real `AttachVirtualDisk`, real drive letter, real file read, real unmount. |

The `IVirtualDiskService` port is what makes the middle row possible. Without it,
every mount test would be an E2E test, and the feedback loop would be a CI round
trip.

## 2. Fixtures

`tools/make-fixtures.sh` runs on macOS and produces the corpus with `hdiutil`.
Fixtures small enough to check in go in `fixtures/`; anything large is generated on
demand and gitignored.

| Fixture | Command shape | Exercises |
| --- | --- | --- |
| `exfat-raw.dmg` | `hdiutil create -fs exFAT -format UDRW` | Raw chunks, the happy path |
| `exfat-zlib.dmg` | `... -format UDZO` | zlib chunks — the main case |
| `exfat-sparse.dmg` | mostly-empty volume, UDZO | Zero-fill and ignore chunks |
| `exfat-enc256.dmg` | `... -encryption AES-256 -stdinpass` | `encrcdsa` v2, AES-256 |
| `exfat-enc128.dmg` | `... -encryption AES-128` | AES-128 key length |
| `fat32.dmg` | `-fs MS-DOS FAT32` | FAT32 probe |
| `hfsplus.dmg` | `-fs HFS+ -format UDZO` | **Negative case** — must refuse with exit 5 |
| `apfs.dmg` | `-fs APFS` | **Negative case** — must refuse with exit 5 |
| `bzip2.dmg` | `-format UDBZ` | **Negative case** — must refuse with exit 3, naming bzip2 |
| `multipart.dmg` | multiple partitions | `--partition` selection |
| `adc.dmg` | `-format UDCO` | Apple ADC decoder |

`fixtures/manifest.json` records the expected SHA-256 of each fixture's fully
decoded sector stream, taken once from `hdiutil convert -format UDTO` output. Every
codec test asserts against that hash, so the decoder is verified against Apple's
own implementation rather than against itself.

### Hostile corpus

Separately, `fixtures/hostile/` holds deliberately malformed images, generated by
mutating good ones:

- truncated at every structural boundary (mid-plist, mid-mish, mid-chunk)
- `CompressedOffset` pointing past EOF
- `CompressedLength` of `0xFFFFFFFFFFFFFFFF`
- `SectorCount` that overflows when multiplied by 512
- a zlib chunk that inflates to 4 GiB (decompression bomb)
- overlapping extents; extents with a gap
- a plist with a billion-laughs entity expansion
- `KdfIterationCount` of 2 000 000 000

The contract for every one of these: a clean non-zero exit with a specific code and
message. **No unhandled exception, no hang, no allocation spike.** These run as
part of `Dmg.Core.Tests` and therefore on the Mac.

## 3. CI

```yaml
# .github/workflows/ci.yml  (shape, not the final file)
jobs:
  core:
    runs-on: macos-latest         # proves the portability constraint holds
    steps: [ make-fixtures, dotnet test tests/Dmg.Core.Tests ]

  windows:
    runs-on: windows-latest
    steps: [ dotnet build, dotnet test tests/Dmg.Core.Tests tests/Dmg.Windows.Tests ]

  e2e:
    runs-on: windows-latest       # GitHub's Windows runners are already elevated
    steps: [ download fixtures, dotnet test tests/Dmg.E2E.Tests ]

  dependency-guard:
    runs-on: ubuntu-latest
    steps: [ fail if any PackageReference exists under src/ ]
```

The `core` job running on **macOS** is not redundant with the `windows` job — it is
the enforcement mechanism for the portability rule. If someone reaches for a
Windows API in `Dmg.Core`, that job goes red immediately.

GitHub's `windows-latest` runners run as an administrator, so `AttachVirtualDisk`
works and the E2E suite can perform genuine mounts. That is the main reason E2E is
viable at all without a self-hosted machine.

## 4. Local Windows testing

For interactive work — watching a mount happen, checking Explorer's behaviour,
testing UAC messaging — CI is not enough.

**Recommended: a Windows 11 arm64 VM under UTM or Parallels on the Mac.** Windows
11 arm64 runs x64 binaries under emulation, and `dmg.exe` can be published for
arm64 directly. Share the repo folder into the VM, publish, run.

The alternative — a Windows container — does **not** work for this project.
Windows containers cannot attach virtual disks; `AttachVirtualDisk` requires
hardware-level device access that container isolation does not provide. Noted here
so it is not attempted twice.

`docs/manual-test-plan.md` (story S10.6) will hold the checklist for the things
only a human at a VM can confirm: Explorer shows the volume with the right label,
eject from Explorer behaves sanely, the UAC message is comprehensible, unmount
after a Explorer window is left open on the drive.

## 5. Test framework

**xUnit**, Apache-2.0, referenced only by projects under `tests/`.

This is the single third-party dependency in the repository and it is never linked
into `dmg.exe`. The alternative — hand-rolling a test runner — would be real work
that tests nothing, and would make every future contributor's life worse. The
dependency guard in CI enforces the boundary rather than the absence.

See [ADR-006](adr/ADR-006-test-framework-exception.md).

## 6. Coverage expectations

Not a percentage target, which measures the wrong thing. Instead, per epic:

| Area | Bar |
| --- | --- |
| Container parsing | Every field validated; every hostile fixture has a test |
| Codecs | Each decoder verified against `hdiutil`-produced ground truth |
| Crypto | Both key sizes; wrong passphrase; capped iteration count; FIPS path |
| Extent index | Boundary reads: first sector, last sector, spanning two chunks, spanning three |
| Cache | Eviction under budget; correctness identical with cache size 0 and 1 GiB |
| Partitions | GPT, MBR, APM, whole-disk, and a multi-partition image |
| Filesystem probe | Every fixture's filesystem correctly identified, including the refusals |
| VHD | Round-trip: written VHD's sectors byte-identical to the source stream |
| Mount | Fake service: every failure branch. Real service: one happy path, one refusal |
| CLI | Every verb's exit code contract, in both human and `--json` modes |

A story is not Done until its area's bar is met.
